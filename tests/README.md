# Tests

Run everything from the repository root:

```
pip install -r requirements.txt
python tests/run_all.py
```

All data is fake and generated by the scripts into `tests/work/` (ignored by git). No real backup or personal data belongs in this repository.

| Script | What it does |
| --- | --- |
| `test_full_backup.py` | Builds a simulated iPhone backup with every supported kind of data (contacts, Messages, WhatsApp, calls, notes, calendar, voicemail, voice memos, Safari, photos, apps) and runs the full export twice (the second run checks incremental export) |
| `make_biz.py` | Copies that backup and adds a WhatsApp Business database with several chats and a group |
| `make_rich.py` | Adds photos across several months, a Live Photo pair, a video, iOS thumbnails and WhatsApp picture messages |
| `test_security.py` | Booby-trapped messages (script injection in the archive pages), files that try to escape the archive folder, and spreadsheet formulas in Excel/CSV. Fails if any gets through |
| `test_phone_window.py` | Opens the real phone window on the fake backup with a **simulated iPhone** (wallpaper, music, books, apps and app files served from memory). Checks the home-screen counts, that every app screen opens (or explains why it's empty), that a save produces a file, and that closing disconnects. Needs a display: Mac and Windows have one; on Linux it runs under `xvfb-run` automatically if installed |
| `test_s1_encryption.py` | S1: the keychain, the strength hint, `phone_write` (refuses unconfirmed writes, logs each one), the password never on a command line or in logs, the CLI without `--password`, and the password dialog. The phone is a stub launcher |
| `test_s3_no_network.py` | S3: installs the in-process network guard, then runs a full backup (stub phone), a full export and a phone-window session, and fails on any internet connection. Also proves the guard refuses the internet and that `Check for updates` is the only, opt-in exception |
| `test_e3_errors.py` | E3: every situation in the spec's table reproduced from real technical text gives its exact message and button; the main window banner and the phone window's inline error show the same plain sentences, technical text behind Show details |
| `test_e1_first_run.py` | E1: the first-run guide walked end to end with a stub iPhone: no phone (three fixes), untrusted (Trust step appears by itself), trusted (password step), Turn on encryption, Back up now, done screen questions (daily, Wi-Fi through `phone_write`), Open iPhone; counts the clicks (2 + password); second launch shows no guide; already-encrypted path |
| `test_e2_helper.py` | E2: the helper's brain with a stub iPhone and no window: Back up now runs a backup, the icon's ring moves, the notification reads "iPhone backed up · N min · X of changes", status lines, failures, Pause, one helper at a time, start-at-login files written to a temporary home, the window's loopback "open" port |
| `test_b2_schedule.py` | B2: the schedule rules with a fake clock (9 pm, phone joins Wi-Fi, same-day skip, 30-minute retries, weekly, only when charging, paused), then the helper itself with a stub iPhone: a backup starts by itself, a restart (new helper from disk) carries on, three missed days give one notification, the amber card line |

These run on every push and pull request in GitHub Actions (`.github/workflows/tests.yml`) on a Mac and a Windows machine.

Every feature adds tests for the points in its "Done when" that can be automated (see `docs/spec/12-engineering.md`).
