# Tests

Run everything from the repository root:

```
pip install -r requirements.txt
python tests/run_all.py
```

All data is fake and generated by the scripts into `tests/work/` (ignored by git). No real backup or personal data belongs in this repository.

| Script | What it does |
| --- | --- |
| `test_full_backup.py` | Builds a simulated iPhone backup with every supported kind of data (contacts, Messages, WhatsApp, calls, notes, calendar, voicemail, voice memos, Safari, photos, apps) and runs the full export twice (the second run checks incremental export) |
| `make_biz.py` | Copies that backup and adds a WhatsApp Business database with several chats and a group |
| `make_rich.py` | Adds photos across several months, a Live Photo pair, a video, iOS thumbnails and WhatsApp picture messages |
| `test_security.py` | Booby-trapped messages (script injection in the archive pages), files that try to escape the archive folder, and spreadsheet formulas in Excel/CSV. Fails if any gets through |
| `test_phone_window.py` | Opens the real phone window on the fake backup with a **simulated iPhone** (wallpaper, music, books, apps and app files served from memory). Checks the home-screen counts, that every app screen opens (or explains why it's empty), that a save produces a file, and that closing disconnects. Needs a display: Mac and Windows have one; on Linux it runs under `xvfb-run` automatically if installed |
| `test_s1_encryption.py` | S1: the keychain, the strength hint, `phone_write` (refuses unconfirmed writes, logs each one), the password never on a command line or in logs, the CLI without `--password`, and the password dialog. The phone is a stub launcher |
| `test_s3_no_network.py` | S3: installs the in-process network guard, then runs a full backup (stub phone), a full export and a phone-window session, and fails on any internet connection. Also proves the guard refuses the internet and that `Check for updates` is the only, opt-in exception |
| `test_e3_errors.py` | E3: every situation in the spec's table reproduced from real technical text gives its exact message and button; the main window banner and the phone window's inline error show the same plain sentences, technical text behind Show details |
| `test_e1_first_run.py` | E1: the first-run guide walked end to end with a stub iPhone: no phone (three fixes), untrusted (Trust step appears by itself), trusted (password step), Turn on encryption, Back up now, done screen questions (daily, Wi-Fi through `phone_write`), Open iPhone; counts the clicks (2 + password); second launch shows no guide; already-encrypted path. 5.2 refresh: four steps on the left with the current one marked and "Step N of 4"; the Trust step offers "Use this iPhone over Wi-Fi", off by default (off writes nothing; on asks by the phone's name; Cancel turns it back off with nothing written; OK is exactly one write through phone_write); Back from the password step; "Type it again" must match; the done side asks no second Wi-Fi question |
| `test_e2_helper.py` | E2: the helper's brain with a stub iPhone and no window: Back up now runs a backup, the icon's ring moves, the notification reads "iPhone backed up · N min · X of changes", status lines, failures, Pause, one helper at a time, start-at-login files written to a temporary home, the window's loopback "open" port |
| `test_b2_schedule.py` | B2: the schedule rules with a fake clock (9 pm, phone joins Wi-Fi, same-day skip, 30-minute retries, weekly, only when charging, paused), then the helper itself with a stub iPhone: a backup starts by itself, a restart (new helper from disk) carries on, three missed days give one notification, the amber card line |
| `test_b3_snapshots.py` | B3: five backups on different days → five snapshots well under five full copies; an older snapshot shows a message deleted since; locked snapshots survive clean-up; garbage collection; rename/delete; format version refused when newer; FAT32 refused with the spec's message; a 4.x backup upgraded (converted, verified, moved) and a failed upgrade leaving it untouched; export from an older snapshot |
| `test_b4_location.py` | B4: backups moved to another folder (copied, verified, old removed) and still open; a bad copy keeps the old one; FAT32 and nested targets refused; an unplugged drive gives "Connect … to back up." (amber, not an error) and nothing is written to its path; the free-space warning; the Location screen |
| `test_x2_redaction.py` | X2: every personal string of the (fake) original is collected, the copy is searched for each one (none found); the copy opens with every section at the same row count; media are same-size placeholders; consistent replacements; CLI takes the password on stdin only |
| `test_b5_open_backup.py` | B5: a Finder-style backup and a PhoneKeep snapshot open in the phone window with no phone connected; Messages appear; All files lists the areas as folders with sizes and dates, previews a single file and saves it with its folder structure; the Open backup dialog lists what PhoneKeep finds; a non-backup folder is refused in plain words |
| `test_c1_cleanup.py` | C1: Photo clean-up on a copy of the rich photo backup with seeded duplicates, near-duplicates, a burst, blurred, dark and overexposed photos, screenshots, a screen recording, a large video and chat-saved images, plus favourite, album, hidden and iCloud-only traps: each card finds exactly what was seeded; saving re-reads each file and compares checksums; the screens walked through; 10,000 photos from a stand-in source timed |
| `test_licence.py` | Licence: LICENSE is gnu.org's GPL v3 text; THIRD_PARTY_NOTICES.md lists every library the app depends on (as installed) with its licence; the PyInstaller recipe and the Windows installer ship both files; the About box and README say the licence; the built app (`--built`, or dist/) contains both files unchanged. build-mac.sh and GitHub's installer builds run it on the app they just built |
| `test_no_owner_names.py` | No real names: the owner's surname (anywhere, even inside a longer word) and the first name (as a word of its own) are in no file git tracks, its path or an image's text bits. Only their salted SHA-256 is in the test; a planted made-up word proves the check finds a word in text, inside a longer word and in a path. History isn't checked |
| `test_theme.py` | Theme (Direction A): theme.py has the agreed colours exactly; no window file writes a colour out (all from theme.py); the main button is accent with white text, a secondary button white with the border colour; the selected row in lists and sidebars is the pale accent; the system font, body 13 pt |
| `test_mac_tabs.py` | Mac window tabs (5.1.2): on a Mac every window (main, phone, Open a backup, viewer, dialogs) is made with `-tabbingmode disallowed`, so macOS can't merge them into tabs whose bar covers the header; every window class is a Toplevel or the main window; older Tk without the option doesn't crash; nothing is called off a Mac |
| `test_reconnect.py` | Reconnect (5.1.3): a live read whose connection drops once reconnects to the same iPhone and retries once; a phone that stays gone gives one plain sentence (also in the Space preview), the header says "Not connected · plug your iPhone back in" in the warning colour and live-only sections say "Plug your iPhone back in to see this" while the backup keeps working; when the same phone comes back (USB or Wi-Fi) the window reconnects by itself and reloads the open section; only this phone's UDID is ever asked for |
| `test_fast_overview.py` | Fast overview (5.1.3): battery, storage and the phone's details come without the app list and show at once; the app list is read only when Storage, Apps or the check-up's Storage details open: names first with "updating sizes…", then sizes 20 apps at a time, then saved per phone and shown at once next time with its date; over Wi-Fi no wallpaper or battery IORegistry is asked for (the saved copies are used) and every query has a short timeout; the timing log is written only when asked for, step names and seconds only |
| `test_main_wallpaper.py` | Main window picture (5.1.3), with an invented home screen: the small phone shows the saved home screen in a dark frame (none saved: the drawn phone); searching dims it with a small turning spinner; not connected dims it with a "not connected" badge; over a cable a fresh one is read once and quietly replaces the saved one, over Wi-Fi nothing is asked; the phone window shows the saved picture at once; no saved picture is in the repo |
| `test_storage_timeout.py` | Storage timeout (5.1.3): with a fake iPhone that holds back an answer, each overview question stands alone (storage, the phone's details or the battery timing out never blanks the rest; a fresh connection after a time-out); the storage helper's second try gives up after its limit; the phone window shows the rest at once with "Storage: waiting for the iPhone…", asks storage again (15 s), shows the figures when it answers, else "The iPhone didn't answer. It may be locked or asleep." with "Try again", and asks again by itself when the iPhone next answers anything or after a minute; `tools/time_phone.py` opens no backup and leaves nothing behind (any end, and at the next start) |
| `test_closed_connection.py` | Closed connection (5.1.3): with a fake iPhone, once a LiveDevice or DevicePhotoSource is closed (the phone went), a read still waiting fails at once as a dropped connection and new reads fail at once with the plain "disconnected" sentence (never a 10-minute wait and "TimeoutError"); a photo source that can't connect leaves no thread; the app list's names and sizes reconnect once on a dropped connection |
| `test_storage_tips.py` | Storage tips (V6, 5.2): with invented apps, each of the 20 largest apps in Storage has a "how to free space" line: by default offloading on the iPhone (Settings → General → iPhone Storage → the app → Offload App), for common big apps (by bundle ID) the app's own way first; showing them asks the phone nothing; PhoneKeep has no way to offload or delete an app itself |
| `test_l1_phone_window.py` | Phone window layout (L1, 5.2, Direction A): with a fake iPhone and invented data, Save everything is the header's main button; the phone picture then the Snapshot card on the left; the three cards, then "What's on this iPhone" as one tile per section in four columns (name and count), then where the data comes from; every tile opens its section and the Battery and Storage cards open their details |
| `test_l2_backup_progress.py` | Backup progress screen (L2, 5.2, Direction A): with a stand-in backup (stub helper, no phone), Back up now puts one card in the window's place with the phone's name, a big percentage, the bar and time left; "Look at your iPhone" shows in the card while the phone waits for its passcode and goes once copying starts; the steps follow what the backup reports (ready, copying, saving the snapshot, then the archive); Cancel stops it and the window comes back saying so |
| `test_l3_settings.py` | Settings layout (L3, 5.2, Direction A): with a test home folder, the list on the left (Backups, Automatic backups, Security, Saving, Activity, About); every card from before is there in the list's order, plus Activity and About; every setting from before is still there (including the app lock, S2, and Only when charging, B2) and still saves; each list item scrolls its cards into view and is highlighted, and scrolling by hand moves the highlight; Activity shows the 5 newest lines of the local record, newest first |
| `test_b9_close_while_backing_up.py` | Keep backing up after the window closes (B9, 5.3): with a stand-in backup (stub helper, no phone; notifications recorded), the card says the window can be closed (an export still says to keep PhoneKeep open); closing the window hides it and the backup carries on, while with nothing running it quits as before; Quit while backing up asks first (Cancel keeps it going, OK stops the backup and quits); the passcode brings the window back with a notification; a backup that doesn't finish notifies why and brings the window back with the problem; one that finishes notifies by the phone's name, then PhoneKeep quits (Windows: the window comes back; not while another PhoneKeep window is open) |
| `test_close_while_reading.py` | Closing a phone window while it is still reading its backup (16 Nov crash): with the tests' invented backup and a read made slow on purpose, closing doesn't make the window wait, the read finishes with its answer, the backup's files are let go right after it, and a later read says the backup was closed |
| `test_e5_all_phones.py` | All phones and backups in one list (E5): with invented phones (two backed up here, one connected over Wi-Fi and never backed up; no real phone), the main window lists each once under "Your iPhones", connected ones first, with name, model and size, when it was backed up, cable / Wi-Fi and the lock badge; with nothing connected, each backed-up phone's card opens a phone window for its own backup; a second click brings that window back; a connected phone that isn't the chosen one opens live and the choice for backing up (B8) stays; with one phone the list is hidden; "Add another iPhone" explains and looks for phones; nothing writes to a phone |

These run on every push and pull request in GitHub Actions (`.github/workflows/tests.yml`) on Linux and Windows; on a Mac by hand (Actions tab) and on release tags.

Every feature adds tests for the points in its "Done when" that can be automated (see `docs/spec/12-engineering.md`).
