# 12. Engineering

## Code map

| File | Responsibility |
| --- | --- |
| `launcher.py` | Entry point: opens the window, runs the command line, or internal helper modes (`--pk-backup` backup with progress lines, `--pk-encryption` password via stdin, `-m pymobiledevice3`) |
| `phonekeep.py` | Core: devices, `make_backup` (progress + status callbacks), `BackupReader` (encrypted or not), WhatsApp loading and export, date filtering, command line |
| `sections.py` | One loader + one writer per kind of data; `export_all` builds an archive and its contents page; `ChatPreview` |
| `tables.py` | Excel and CSV writers with formula protection |
| `photos.py` | Photo sources: from a backup, or live from the phone; thumbnails; Live Photo pairing |
| `device.py` | Live, read-only access: wallpaper, music library, books, apps and their shared documents |
| `ui.py` | Colours, fonts, buttons, chips; `ChatPanel` and `PhotoPanel` used by the pickers and the phone window |
| `app.py` | Main window: device card, what-to-keep tiles, progress, done card, Settings |
| `phone.py` | Phone window: phone picture with wallpaper, app grid, one screen per app, saving, refresh |
| `packaging/` | PyInstaller spec (also builds the `phonekeep-cli` helper), Windows installer script, icon maker |
| `.github/workflows/build-installers.yml` | Builds Mac (Apple Silicon, Intel) and Windows installers |

Talks to the iPhone through **pymobiledevice3** (open source); decrypts backups with **iphone_backup_decrypt**; images with **Pillow** / **pillow-heif**; spreadsheets with **openpyxl**.

## Architecture rules

- **One module per kind of data**, each with a loader (returns plain data) and a writer (saves files). The phone window and exports both use the loader; never parse the same database twice in different places.
- **UI never blocks:** device and backup work runs in background threads; results come back to the UI thread through a queue.
- **Anything that writes to the phone** goes through one module (`phone_write.py`, to create) that performs the confirmation check and the activity log entry. No other module may call a phone write API.
- **Paths from the phone or a backup** always go through `safe_join` / `safe_local`.
- If the UI is rebuilt in a native toolkit (SwiftUI on Mac, WinUI on Windows), keep the Python core as the engine behind a small local interface; do not rewrite the data code without agreement.

## Tests

- Test scripts must live in `tests/` in the repository and run on every push in GitHub Actions (Mac and Windows).
- Existing test scripts to bring in: full fake backup of every kind of data; WhatsApp + WhatsApp Business backup; rich photo backup (months, Live Photos, videos, thumbnails); security tests (script injection, path escapes, spreadsheet formulas); phone-window actions with a simulated iPhone.
- Every feature adds tests for its **Done when** points that can be automated.
- Keep a library of **anonymised real backups** from several iOS versions for regression tests; never commit real personal data.
- Visual checks (screenshots of every screen, light and dark) are generated by a script and attached to pull requests that change the UI. Check them on a real Mac.

## Build and release

- Version number lives in `phonekeep.py` (`VERSION`), `packaging/PhoneKeep.spec` and `packaging/PhoneKeep.iss`; change all three together.
- **Build installers** workflow: run from the Actions tab or by pushing a tag `vX.Y.Z` (which also publishes a GitHub Release with installers and checksums).
- Releases follow the definition of done in [README.md](README.md), including the usability test in [00-user-experience.md](00-user-experience.md).

## Command line

Every feature that saves or backs up also works from the command line (`phonekeep-cli`), with the same options as the window, for automation. Existing commands: `devices`, `backups`, `backup`, `run`, `export` (`--only`, `--chats`, `--formats`, `--from`, `--to`), `whatsapp`, `photos`, `encryption on|off`.

## Out of scope (do not build without written agreement)

| Not building | Why |
| --- | --- |
| Installing or downloading apps (.ipa) | Only the App Store may do this |
| Updating or restoring iOS, recovery and DFU modes | High risk of data loss; Apple's own tools do it |
| Company device management (supervision, MDM, configuration profiles) | Different audience |
| Developer tools (location simulation, network capture, system logs, pairing records) | Different audience; adds risk |
| Signed legal-evidence exports and e-discovery formats | Different audience |
| Any cloud service, account or online sync | Conflicts with "data stays on the computer" |
| Reading Signal | Signal keeps its data out of backups |
