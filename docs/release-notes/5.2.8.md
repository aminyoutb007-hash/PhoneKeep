# PhoneKeep 5.2.8

The storage map's Photos now count what the iPhone keeps for the Photos app, Recently Deleted included, and a few safety fixes for when a phone window reads a backup. Everything in [the 5.2.7 notes](https://github.com/aminyoutb007-hash/PhoneKeep/blob/main/docs/release-notes/5.2.7.md) is still true, plus what's below.

**Verified on a Mac (Apple Silicon) with a real iPhone. The Windows check is deferred:** every automated test runs on Windows on each change, but no check with a real iPhone on a Windows PC was done for this release.

## Fixed

- **The storage map's Photos count what's on the iPhone for the Photos app.** With iCloud Photos, the photos and videos the iPhone has downloaded back from iCloud sit in a different folder from the camera's own. The map and the Storage screen counted only the camera's folder. Now they count both. Photos kept only in iCloud take no space on the iPhone and aren't counted.
- **Recently Deleted on the storage map.** Photos and videos in the Photos app's Recently Deleted still take space until the iPhone empties it. The map's Photos level now shows them as their own block, "Recently Deleted", and says that. It shows only what the Photos library marks as deleted.
- **The map's videos are the ones the Photos app lists.** A Live Photo's moving part is part of the photo, not a separate video, as in the Photos app and Photo clean-up. A video file the Photos app doesn't list counts as other files.
- **One more case of closing a phone window while it saves a photo.** 5.2.7 fixed this for photos read from the backup. A photo that had already been copied out of the backup (to make its thumbnail) could still fail to save with "file not found" if the window closed at that moment. Now that save finishes first too.
- **Smaller safety work when the phone window reads a backup:** the Apps list reads its file counts with the backup held open, and the backup's photo list is made only once even if two parts of the window ask for it at the same time (today only one part asks, so this is a safeguard).
- **The tamper check's record forgets deleted snapshots.** When PhoneKeep deletes a snapshot (Delete… or the automatic clean-up), its entry leaves the record of seals, so the record no longer grows for ever. A snapshot that is only missing (its drive unplugged) keeps its entry.

## Known limits

- Everything in [the 5.2.7 notes' Known limits](https://github.com/aminyoutb007-hash/PhoneKeep/blob/main/docs/release-notes/5.2.7.md#known-limits) is still true.
- Save everything's estimate of the space your photos need still counts only the camera's folder, not the photos downloaded back from iCloud.
