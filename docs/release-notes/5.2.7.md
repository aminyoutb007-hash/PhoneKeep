# PhoneKeep 5.2.7

Two fixes: the storage map keeps up with the iPhone, and closing a phone window while it saves a photo from a backup no longer breaks that save. Everything in [the 5.2.6 notes](https://github.com/aminyoutb007-hash/PhoneKeep/blob/main/docs/release-notes/5.2.6.md) is still true, plus what's below.

**Verified on a Mac (Apple Silicon) with a real iPhone. The Windows check is deferred:** every automated test runs on Windows on each change, but no check with a real iPhone on a Windows PC was done for this release.

## Fixed

- **The storage map follows app sizes as they arrive.** The iPhone sends its app sizes a little at a time. The map now redraws as they come in, on its top level and in Apps, and says so while they're still coming ("The iPhone is still sending app sizes, so Apps, System and Other change as they come in."). Before, it kept the first figures until you opened it again. The path links above the map now open the phone's newest figures too.
- **Closing a phone window while it saves a photo from a backup.** When the photos come from the backup (the iPhone is locked or not reachable), closing the window could close the backup under a photo being saved or a thumbnail being made. Now the save finishes first, and nothing reads the backup once it's closed.

## Changed

- The library PhoneKeep uses to talk to the iPhone (pymobiledevice3) is a newer version, checked with a real iPhone.

## Known limits

- Everything in [the 5.2.6 notes' Known limits](https://github.com/aminyoutb007-hash/PhoneKeep/blob/main/docs/release-notes/5.2.6.md#known-limits) is still true.
